wvd — WireView 측정 데몬 · 대시보드 설계안

2026-10-07 · 대상 기기: Thermal Grizzly WireView Pro II (EF05) / Noctua Edition (EF06)

/dev/ttyACM0를 단일 프로세스가 소유하고, 측정값을 웹 대시보드 · REST/WebSocket API · CLI 세 경로로 동일하게 제공한다. 목표는 사람 없이 테스트 코드가 측정·구간 통계·합격 판정까지 수행하는 자율 테스트.

실측 결과

0.2 ms센서 읽기 지연 (p50, p99 0.3 ms)

공식 GUI는 1 Hz로 폴링하지만, 기기는 약 16 ms마다 값을 갱신하고 응답도 즉시 돌려준다. 따라서 기본 10 Hz, 최대 50 Hz로 잡는다. 측정 기기: FW TG-WV-PRO2-FW_20260430_1838.

시리얼 프로토콜 (실기기 검증)

115200 8N1 raw. 프레이밍·CRC 없음: 입력 버퍼 flush → 명령 1바이트 write → 고정 길이 read (1 s 타임아웃).

명령코드응답내용
READ_VENDOR_DATA0x013 Bvendor, product, fw 버전 (예 ef 05 05)
READ_UID0x0212 B칩 UID
READ_SENSOR_VALUES0x04100 B센서 구조체 (아래)
READ_BUILD_INFO0x0D68 Boffset 35부터 32 B 빌드 문자열
CLEAR_FAULTS0x0E없음+ keepStatusMask u16, keepLogMask u16 (LE)
센서 프레임 100 B, little-endian, Python struct: "<4hHBx" + "h2xII"*6 + "IIHBxHH"
  Ts[4] int16 0.1°C (in, out, ext1, ext2) | Vdd u16 mV | FanDuty u8 % | pad
  6 × { Voltage int16 mV, pad2, Current u32 mA, Power u32 mW }
  TotalPower u32 mW | TotalCurrent u32 mA | AvgVoltage u16 mV | HpwrCap u8 (0=600 1=450 2=300 3=150 W) | pad
  FaultStatus u16 | FaultLog u16
손상 판정 (원본과 동일): buf[10] > 100 or buf[11] != 0 or buf[95] != 0
Fault 비트: 0 OTP_TCHIP · 1 OTP_TS · 2 OCP · 3 WIRE_OCP · 4 OPP · 5 CURRENT_IMBALANCE
프레이밍이 없으므로 포트는 반드시 한 프로세스만 연다. wvd는 TIOCEXCL로 포트를 배타적으로 잡는다. 기존 GUI와 wireviewd는 함께 띄우지 않는다.

1) 백엔드 데몬 wvd

Python 3.10+, asyncio + FastAPI/uvicorn. 시리얼은 stdlib termios만 사용 (pyserial 불필요).

1.2부터 프로세스 3개로 나뉜다. wvd 명령은 감독(supervisor)만 하고, 자식이 죽으면 1초 뒤 다시 띄운다(60초에 5번 넘으면 종료 코드 70 → systemd 재시작). 프로세스마다 GIL이 따로라서, 무거운 조회가 수집이나 실시간 스트림을 늦추지 못한다.

/dev/ttyACM0 ─ recorder ── Sampler(스레드) ─ Event 엔진 ─ writer ─ SQLite (샘플·이벤트 기록)
   (단독 소유)     └─ 피드(Unix 소켓, NDJSON) ─┬─▶ front  :8765  대시보드 · WS/SSE · latest · health · /metrics
                                               └─▶ api   (Unix 소켓) history · stats · export · 세션
                   ◀─ 제어(Unix 소켓): 폴트 해제, 세션 변경 알림 ─ api
   front ── 나머지 /api/* 요청을 api로 전달(프록시), 인증은 front에서
계층역할
Transportraw 115200 8N1, TIOCEXCL 배타 오픈, sysfs로 VID:PID 0483:5740 포트 자동 탐색, 언플러그 시 자동 재연결. --simulate 시 가상 기기.
Protocol명령/응답, 100 B 디코딩, 손상 프레임 검사. vendor 데이터로 EF05/EF06만 수용.
Sampler단조 시계 기반 고정 주기 폴링, 샘플마다 seq·timestamp, 연속 6회 실패 시 연결 해제. 쓰기 명령도 이 스레드가 직렬 실행.
Store링버퍼(최근 15분, 실시간) + SQLite WAL(원본 100 B 프레임 BLOB 저장, 기본 보관 72 h). 세션 구간 데이터는 보관 기간과 무관하게 영구 보존.
Event 엔진FaultStatus/FaultLog 비트 변화, 임계값 진입/해제(히스테리시스), 연결 끊김/복구 → 저장 + 푸시.

pin_imbalance = 최대 핀 전류 ÷ 평균 핀 전류 (1.0 = 완전 균형). 12V-2x6 커넥터 용융 위험의 핵심 지표다. 총 전류가 1 A 미만이면 의미가 없어 null. 에너지(Wh)는 구간 통계에서 적분한다.

운영

  • systemd 서비스 (dialout 그룹), udev 규칙(packaging/70-wireview.rules)이 권한과 /dev/wireview-pro2 심링크를 제공.
  • 보안: 기본 0.0.0.0 바인딩(LAN에서 바로 접속 가능). 토큰이 없으면 읽기는 누구나 가능하고 시작 시 경고를 남긴다. --token(Bearer, WS는 ?token=)을 주면 인증을 요구한다. 토큰 없이 외부 바인딩에서 --allow-write를 켜면 시작을 거부한다. TLS는 리버스 프록시에 맡긴다.
  • 시뮬레이터: wvd --simulate idle|load|imbalance|fault. 하드웨어 없이 CI에서 전체 경로를 검증한다. 시뮬레이터도 100 B 프레임을 인코딩해서 내보내므로 디코딩 경로까지 함께 테스트된다.
  • 다중 기기 대비: 내부 키를 UID로 두어 확장이 가능하게 한다 (현재는 단일 기기).

2) 웹 대시보드

빌드 단계 없는 정적 페이지(HTML + ES modules) + uPlot 시계열 차트. wvd가 /에서 직접 서빙한다. 대시보드도 API 클라이언트 중 하나일 뿐이다.

┌ 헤더: ● 연결 | WireView Pro II · FW | PSU 600W | 폴트 배지 | 세션 시작/정지 ┐
├ KPI: 총 전력 · 총 전류 · 평균 전압 · 최고 온도 · 핀 불균형                   ┤
├ 핀 패널: 6핀 전류 막대 + 임계값 선, 핀별 V/A/W                              ┤
├ 차트 (1m/5m/15m/1h): 총 전력 · 핀별 전류 · 핀별 전압 · 온도                 ┤
└ 하단: 이벤트 타임라인 · 세션 목록(통계, CSV) · 기기 정보                     ┘
  • 초기 로드 history → WebSocket으로 이어 붙임 → 재연결 시 after_seq로 끊긴 구간 보충.
  • 임계값은 /api/v1/limits에서 받아 화면 경고와 CLI/API 판정에 같은 기준을 적용한다.
  • 여러 명이 동시에 봐도 기기에는 데몬 하나만 접근한다. 라이트/다크 테마, 모바일 폭 지원.

a. CLI · API 접근

세 경로 모두 같은 데몬과 같은 스키마를 쓴다. wvclient(의존성 없는 Python 클라이언트) 위에 CLI wvctl을 만든다.

wvctl info                               # 기기 정보
wvctl now [--json]                       # 현재값
wvctl watch                              # 실시간 갱신 (SSE)
wvctl log --duration 60s -o run.csv      # 기록 (csv/jsonl)
wvctl stats --last 5m [--json]           # 구간 통계
wvctl session start "load-A" / session stop [--json]
wvctl assert --duration 30s --max-total-w 600 --max-pin-a 9.5 --max-temp 70 --no-faults
                                         # 통과 0 / 위반 1 / 오류 2 → CI에서 바로 판정
wvctl --url http://host:8765 --token … # 원격 데몬
from wvd.client import WireView
wv = WireView("http://127.0.0.1:8765")
with wv.session("gpu-stress-01") as s:
    run_gpu_stress(60)
st = s.stats()
assert st["fields"]["total_w"]["max"] < 600 and not st["faults_seen"]

pytest fixture wireview를 제공한다. WVD_URL이 있으면 그 데몬을 쓰고, 없으면 시뮬레이터 데몬을 자동으로 띄운다. REST는 curl/Go/JS 어디서나 쓸 수 있고, /metrics로 Grafana에도 연결된다.
