프로세스스레드·역할다른 쪽이 바쁠 때
recorder
wvd/recorder.py		수집, writer, 구독자별 전송 스레드, 제어, 1초마다 상태 발행. 디코딩이나 통계 같은 무거운 일은 하지 않는다.구독자가 느리면 그 구독자에게 보낼 실시간분만 버린다(feed_dropped). DB에는 빠짐없이 기록한다.
front
wvd/front.py		asyncio만 쓴다. 피드에서 받은 메시지를 다시 인코딩하지 않고 WS로 그대로 보낸다. SSE용 변환은 메시지당 한 번만 한다.무거운 조회가 front에 들어오지 않는다.
api
wvd/api.py		조회, 세션, export. 피드로 채운 링 버퍼로 아직 기록되지 않은 구간까지 조회한다.무겁게 돌아도 수집과 스트림에 영향이 없다. 동시 실행 제한(2개)은 그대로 유지한다.
supervisor
wvd/daemon.py		recorder → api → front 순서로 띄우고, 각자 소켓이 준비될 때까지 기다린다. 종료는 반대 순서로 해서 recorder가 마지막에 남은 기록을 마무리한다.–

프로세스 사이 통신(wvd/bus.py)은 비공개 디렉터리(/run/wvd, 권한 0700)의 Unix 소켓 세 개로 한다.

  • feed.sock: recorder → 구독자 방송
  • control.sock: 요청 한 줄에 응답 한 줄
  • api.sock: api의 HTTP

인증은 front에서만 검사한다. api 소켓은 외부에서 접근할 수 없다.

장애와 재시작

상황동작확인 방법
USB 오류(EIO)recorder 안에서 연결을 끊고 재연결한다. 프로세스는 재시작하지 않는다.테스트: read-termios:25
수집 스레드 사망recorder가 종료 코드 70으로 끝나고, supervisor가 1초 뒤 다시 띄운다. API와 대시보드 연결은 유지된다.테스트: kill:100. health가 즉시 down → 다시 ok
api 또는 front 강제 종료1초 뒤 다시 띄운다. recorder는 계속 수집한다(공백 0).테스트: SIGKILL 후 gaps_total == 0
연속 재시작60초에 5번 넘으면 wvd가 종료 코드 70으로 끝난다. 그다음은 systemd가 맡는다.테스트: kill:5 → 종료 코드 70
supervisor 강제 종료자식이 모두 종료되어 시리얼 포트가 풀린다.테스트: SIGKILL 후 자식 pid가 모두 사라짐
DB 지연수집은 계속된다. api는 아직 기록되지 않은 구간을 링 버퍼에서 응답한다.테스트: db-slow:1.5, 최대 공백 0.3 s 미만

seq와 이벤트 id는 재시작해도 겹치지 않는다. writer가 meta 테이블에 상한값(2분분 여유)을 기록하고, 새 recorder는 그 위에서 번호를 시작한다. 따라서 recorder가 재시작되면 seq가 앞으로 건너뛴다. 멈췄던 구간은 첫 샘플의 gap_s와 sampler.gap 이벤트로 드러난다.

API 변화 (1.1 대비)

  • health 추가 항목
    • processes: 프로세스별 pid, 재시작 횟수, 마지막 종료 코드
    • api_ok, recorder_status_age_s, feed_connected, feed_dropped
  • status 판정
    • down: recorder가 없거나 재시작 중일 때. 피드 연결이 끊기는 순간 바로 판정한다.
    • degraded: api가 응답하지 않을 때도 포함된다.
  • /metrics: wvd_process_restarts_total{process=…} 추가
  • 바뀌지 않은 것: 샘플 형식, 엔드포인트 경로, CLI, Python 클라이언트, 대시보드

배포 기록 (2026-10-07 21:30)

  1. /opt/wvd에 1.2.0 설치. 새 의존성은 httpx이다.
  2. 서비스 정지 후 DB 백업: /var/lib/private/wvd/wvd.db.bak-1.0-202610072130 (139 MB, root 소유)
  3. 유닛 파일 갱신(RuntimeDirectory=wvd 추가) 후 시작. 50 Hz 드롭인은 그대로 둔다.
  4. 기존 DB를 그대로 쓴다. 새 열 samples.gap, sessions.stats와 새 테이블 meta가 자동으로 추가됐다.
  5. 수집이 끊긴 시간은 0.43초였다. 이 구간도 last_gap에 기록됐다.
  6. 다른 PC 대시보드 두 대(192.168.1.20, .146)는 재시작 1초 뒤 자동으로 다시 연결됐다.
  7. 실제 기기 부하 시험을 통과했다. 시험이 만든 세션은 모두 지워졌다.

git: main을 fast-forward로 병합하고 v1.1.0, v1.2.0 태그를 붙였다. origin에는 push하지 않았다.

다시 배포하는 절차는 다음과 같다. 설치 때 생기는 build/ 디렉터리가 root 소유라서 지워야 한다.

sudo /opt/wvd/bin/pip install "$PWD[server]" && sudo rm -rf build
sudo cp packaging/wvd.service /etc/systemd/system/ && sudo systemctl daemon-reload
sudo systemctl restart wvd

seriesA 참고

  • 공백은 seq로 판단하지 않는다. seq는 수집이 멈춘 구간에도 비지 않고, recorder가 재시작되면 앞으로 건너뛴다. gap_s나 ts 간격을 쓴다.
  • guard의 지연 검사는 now - sample.ts로 한다. 스트림 전달 지연이 최대 수십 ms라서, 샘플 정지 기준을 5초에서 3초로 되돌릴 근거가 된다(리뷰 7장의 결정 항목).
  • 사전 점검에는 health의 status, gaps_total, max_gap_s_5m, processes[*].restarts를 쓴다.
  • lag 메시지를 받으면 그 구독자가 밀렸다는 뜻이다. 빠진 구간은 /sensors/history?after_seq=로 다시 받는다.
